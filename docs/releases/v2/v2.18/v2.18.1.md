This is a new patch release of the `alex-c-line` package. It includes small, non-breaking changes and should require no refactoring. Please read the description of changes below.
<!-- alex-c-line-release-summary-end -->

## Description of Changes

<!-- user-editable-section-start -->
- Refactor the error handling throughout the codebase.
  - We now have an internal `ProgramError` class that the CLI's error handler then delegates to `program.error`.
  - This allows these errors to then be treated like they would any other error class where we can more easily catch them, or create other error classes extending it.
  - For example, the internal `UserError` class also introduced in this release extends `ProgramError` and standardises the fact that exit code 2 in this project refers to errors as a result of user actions.

## Additional Notes

- This follows a similar pattern to the error refactor in Lexicon, where we have an `APIError` class that can be thrown as usual throughout the codebase, and then the error handlers decide how to present the error to users.
- In the case of Lexicon, though, we also had to account for the possibility of errors being thrown from the service layer that may not necessarily be thrown from the API layer. For example, a service function getting used in the workers. This is not a concern for `alex-c-line` as the CLI is pretty much the only way to interact with it as of now, but I think this refactor does prepare us for if this may change later.
