## Description of Changes

<!-- user-editable-section-start -->
- Account for nullable `patched_versions` in the security audit
  - This is actually a nullable property and so the dependency audits broke recently because of that.
  - A nullable `patched_versions` field generally corresponds to there not being a fix available if `patched_versions_unpublished` is also true, otherwise I think it just means that it is unknown what version contains the patch.

## Additional Notes

- I guess in theory it is probably fine to leave as is - if there is no patched version available, do we really want to accept the current version knowing there is no fix yet?
- That said, I think, given that this is a report it's probably better to have it pass but let us know that there is no patch yet.
- Really, though, I need to add some configuration options to the dependency audits at some point to allow the user to customise exactly to what extent the audits should fail. But that's for another time.
